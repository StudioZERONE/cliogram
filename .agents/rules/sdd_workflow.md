# 명세 주도 개발 (Spec-Driven Development, SDD) 아키텍처 규칙

> 본 규칙은 CLIOGRAM 프로젝트에서 기능 추가 및 화면 개발 시 준수해야 하는 **명세 주도 개발(SDD)의 목적, 비전, 역할 분담 및 5단계 이행 체계**를 정의합니다.

---

## 1. 목적 및 비전 (Purpose & Vision)

- **목적 (Purpose)**:
  - 임의의 임시 구현이나 주먹구구식 코드 수정을 전면 차단하고, DB 데이터 구조, API, UI/UX, 자동화 테스트 사양을 **선행 정의(Spec-First)**한 후 개발에 착수합니다.
  - 데이터 진실성(Strict Data Truth)과 무결성을 100% 유지하며 회귀(Regression) 오류 발생을 사전에 완벽히 방지합니다.

- **비전 (Vision)**:
  - **CEO(영일님)**는 아이디어와 비전에 집중하고, **CTO(AI 에이전트)**가 설계 문서화, 테스트 코드 작성, 프로덕션 구현, 실증 검증까지 전 과정을 자율 구동하는 최고 수준의 개발 생산성 체계를 구축합니다.

---

## 2. 역할 분담 규정 (Role Boundaries)

- **CEO (영일님)**:
  - **아이디어 및 요구사항 제공 (What & Why)**: 새로 추가하거나 변경하고 싶은 화면/기능의 목적과 필요 요소를 자연어로 전달.
  - **설계서 검토 및 승인**: AI 에이전트가 작성한 SDD 설계서의 기획 방향을 확인하고 승인/수정 지시.

- **CTO (AI 에이전트)**:
  - **SDD 설계서 자동 생성**: 영일님의 요구사항을 반영하여 `41.01` 규격의 명세서(DB, API, UI, 테스트 스펙 포함) 초안 자동 작성.
  - **Test-First 기반 자율 구현**: 명세서에 정의된 사양에 따라 Vitest 자동화 테스트 코드를 선행 작성하고 프로덕션 코드 구현.
  - **실증 검증 및 커밋/푸시**: 테스트 통과 결과(Pass Count)와 빌드 통과를 보고하고 자율 커밋(`git commit & push`) 완료.

---

## 3. SDD 진행 워크플로우 5단계 (5-Step Lifecycle)

1. **Step 1. 요구사항 공유 (영일님 → AI 에이전트)**
   - 개발하고자 하는 기능/화면에 대한 설명 및 아이디어 전달.

2. **Step 2. SDD 설계서 작성 (AI 에이전트)**
   - `41.01.시스템 공통코드 명세 주도 개발(SDD) 설계서` 표준 규격에 따라 기능 설계 문서 작성.
   - DB 테이블/쿼리 명세, API 앤드포인트, UI/UX 컴포넌트 명세, Vitest 검증 항목 포함.

3. **Step 3. 명세 검토 및 승인 (영일님)**
   - 작성된 SDD 설계서를 영일님이 검토 후 최종 승인 (필요시 항목 수정 요청).

4. **Step 4. Test-First 개발 및 100% 검증 (AI 에이전트)**
   - Vitest 테스트 코드를 선행 수립하고 100% 통과(Pass)할 때까지 프로덕션 코드 완성.

5. **Step 5. 실증 보고 및 자율 반영 (AI 에이전트)**
   - 테스트 실행 건수/통과 수치(Pass Count) 및 빌드 결과를 영일님께 보고하고 Git 저장소 반영 완료.

---

## 4. SDD 설계서 포함 필수 4대 영역

1. **기능 개요 및 비즈니스 목적**: 무엇을 왜 만드는가?
2. **DB 스키마 및 Strict Query 명세**: 어떤 테이블과 정렬된 SQL/ORM 쿼리를 사용하는가?
3. **UI/UX & 컴포넌트 명세**: 화면 레이아웃, 컬러 토큰(`bg-emerald-500/10` 등), 인터랙션 규칙.
4. **Vitest 자동화 테스트 스펙**: 검증해야 할 핵심 단위/인티그레이션 테스트 케이스 목록.
